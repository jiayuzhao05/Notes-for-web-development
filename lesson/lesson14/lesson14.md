\*作业：了解以太网工作原理
数据链路层（Layer 2）的技术规范，定义局域网内设备如何连接、传输数据和识别设备。

工作在数据链路层（OSI 第 2 层）
使用 MAC 地址识别设备
只能在局域网（LAN）内传输
支持有线（Ethernet）和无线（WiFi）两种形式

以太网以帧（Frame）为单位传输数据
+--------+--------+--------+--------+--------+--------+--------+--------+
| 前导码 | 目标 MAC| 源 MAC | 类型 | 数据 | 填充 | FCS |
| 7 字节 | 6 字节 | 6 字节 | 2 字节 | 46-1500| 0-46 | 4 字节 |
+--------+--------+--------+--------+--------+--------+--------+--------+
前导码（Preamble）：用于同步，让接收方准备接收数据；固定模式：10101010...
目标 MAC 地址（Destination MAC）：接收方的 MAC 地址（BB:BB:BB:BB:BB:BB）
源 MAC 地址（Source MAC）：发送方的 MAC 地址（AA:AA:AA:AA:AA:AA）
类型/长度：0x0800：IPv4；0x0806：ARP；0x86DD：IPv6
数据（Payload）：包含上层协议数据（IP 数据包）；最小 46 字节，最大 1500 字节（MTU）
填充（Padding）：如果数据小于 46 字节，需要填充到 46 字节
FCS（Frame Check Sequence）：帧校验序列，用于检测传输错误

2.CSMA/CD 机制（载波监听多路访问/冲突检测）
以太网使用 CSMA/CD 来协调多设备共享同一物理介质

1. 监听（Carrier Sense）
   ↓
   检测网络是否空闲
   ↓
2. 发送（Multiple Access）
   ↓
   如果空闲，立即发送
   如果忙碌，等待随机时间后重试
   ↓
3. 冲突检测（Collision Detection）
   ↓
   发送时继续监听
   如果检测到冲突，立即停止发送
   ↓
4. 退避（Backoff）
   ↓
   等待随机时间后重新尝试

## B MB GB 区别？

1 B = 8 bits（8 个二进制位） 一个字符（ASCII）
计算机用二进制
1 KB = 2^10 B = 1024 B 约 1 页纯文本
1 MB = 1024 KB = 2^20 B = 1,048,576 B 约 500 页文本，1 张照片
1 GB = 1024 MB = 2^30 B = 1,073,741,824 B 约 250 首歌，1 部电影
1 TB = 1024 GB = 2^40 B = 1,099,511,627,776 B 约 250,000 首歌，500 部电影

厂商用十进制
1 KB = 1000 B
1 MB = 1000 KB = 1,000,000 B
1 GB = 1000 MB = 1,000,000,000 B

为什么需要三次？
两次无法确认服务器是否收到客户端连接需求，3 次双方都能确认对方收到了自己的请求

第一次握手：client->server 发送 SYN 报文
TCP 报文头部：
+------------------+------------------+
| 源端口 | 目标端口 |
| 54321 | 80 |
+------------------+------------------+
| 序列号（seq） | |
| 100 | |
+------------------+------------------+
| 确认号（ack） | |
| 0 | （未设置） |
+------------------+------------------+
| 数据偏移 | 保留 | 标志位 |
| 5 | 000 | SYN=1, ACK=0 |
+------------------+------------------+
| 窗口大小 | 校验和 |
| 65535 | 0x1234 |
+------------------+------------------+
SYN = 1：请求建立连接
ACK = 0：确认号无效（第一次握手）
seq = 100：客户端初始序列号（ISN，Initial Sequence Number）（初始序列号（ISN）是随机生成的；发送数据后，序列号 = 原序列号 + 数据长度）标识数据字节
ack = 0：未设置（因为还没有收到服务器的数据）（确认号 = 收到的序列号 + 1 表示"我期望收到下一个序列号"）
窗口大小 = 65535：客户端接收缓冲区大小

第二次握手：server->client(SYN-ACK 报文)
TCP 报文头部：
+------------------+------------------+
| 源端口 | 目标端口 |
| 80 | 54321 |
+------------------+------------------+
| 序列号（seq） | |
| 200 | |
+------------------+------------------+
| 确认号（ack） | |
| 101 | （期望收到 101） |
+------------------+------------------+
| 数据偏移 | 保留 | 标志位 |
| 5 | 000 | SYN=1, ACK=1 |
+------------------+------------------+
| 窗口大小 | 校验和 |
| 65535 | 0x5678 |
+------------------+------------------+
ack = 101：确认收到客户端的 seq=100，期望下一个是 101
窗口大小 = 65535：服务器接收缓冲区大小

第三次握手：client->server(ACK)
TCP 报文头部：
+------------------+------------------+
| 源端口 | 目标端口 |
| 54321 | 80 |
+------------------+------------------+
| 序列号（seq） | |
| 101 | （已确认） |
+------------------+------------------+
| 确认号（ack） | |
| 201 | （期望收到 201） |
+------------------+------------------+
| 数据偏移 | 保留 | 标志位 |
| 5 | 000 | SYN=0, ACK=1 |
+------------------+------------------+
| 窗口大小 | 校验和 |
| 65535 | 0x9ABC |
+------------------+------------------+
SYN = 0：不再发送 SYN（连接已建立）
ack = 201：确认收到服务器的 seq=200，期望下一个是 201 确认标志 表示确认号有效
